# Step 2 — viscous analysis

Goal: a faithful Rust port of XFOIL 6.996's viscous–inviscid interaction
(integral boundary layer, eᴺ transition, wake, drag), validated against
XFOIL itself, then exposed in the desktop application.

## Scope of the port

| XFOIL | Content | Rust |
|---|---|---|
| `xblsys.f` | closure relations (`HKIN`, `HSL`, `HST`, `CFL`, `CFT`, `HCT`, `DIL`, `DILW`, `DAMPL`, `DAMPL2`), station variables (`BLPRV`, `BLKIN`, `BLVAR`, `BLMID`), interval equations (`BLDIF`, `TRDIF`, `TESYS`, `BLSYS`), transition (`TRCHEK2`, `AXSET`) | `viscous::closure`, `viscous::blsys` |
| `xpanel.f` | wake (`XYWAKE`, `PSWLIN`, `QWCALC`), source influence (`QDCALC`), stagnation point and BL stations (`STFIND`, `IBLPAN`, `XICALC`, `STMOVE`), edge velocities (`UICALC`, `UESET`, `QVFUE`, `QISET`, `GAMQV`) | `viscous::wake`, `viscous::stations` |
| `xbl.f` | marching (`MRCHUE`, `MRCHDU`, `DSLIM`), global Newton system (`SETBL`, `IBLSYS`, `UPDATE`), trips (`XIFSET`), constants (`BLPINI`) | `viscous::march`, `viscous::newton` |
| `xsolve.f` | `GAUSS`, block solver `BLSOLV` | `viscous::newton` |
| `xoper.f`, `xfoil.f` | `VISCAL` iteration, `CDCALC`, `ASEQ` sequence semantics | `viscous::solver` |

Not ported: Mach/Reynolds varying with CL (`MATYP`, `RETYP` ≠ 1), flap hinge
moments, inverse design.

Formulation details reproduced on purpose:

- the common variable `HVRAT` of the viscosity law is never assigned in
  XFOIL's solver, so it is 0 (μ ∝ √T); only the plotting routines use 0.35;
- `BLSOLV` drops the off-diagonal mass-influence terms below `VACCEL`
  (0.01), as XFOIL does;
- sequences warm-start each point from the previous boundary layer, with
  XFOIL's iteration limits (20 for a single point, 25 in a sequence) and its
  convergence test (rms of the normalized changes < 10⁻⁴).

## Sub-steps

Each sub-step: code, tests, `clippy -D warnings`, commit; no progress while a
test fails.

- **V0** — reference data: viscous runs in `tests/reference/generate.py`
  (one XFOIL session per run, polar + unformatted dump with full-precision BL
  data, cold-started single points with `CPWR`/`DUMP`), ten cases in
  `tests/viscous`, generated by the `xfoil-reference` workflow.
- **V1** — closure relations and the station/interval systems, with
  finite-difference checks of every Jacobian.
- **V2** — wake geometry, wake source influence, stagnation point and BL
  stations, compared with XFOIL's `DUMP` (wake coordinates, ξ).
- **V3** — marching, global Newton system, block solver, update, `VISCAL`,
  `CDCALC`; first comparisons with XFOIL.
- **V4** — validation: sequences reproduced point by point (polar files and
  dump files), single points, a random extended set as for the inviscid
  solver, mutation testing.
- **V5** — public API: `ViscousOptions` (Re, Mach, Ncrit per side, trips,
  iteration limit), single points and warm-started sweeps with convergence
  flags, boundary-layer distributions in the outputs.
- **V6** — application: viscous toggle, Re/Ncrit/trip inputs, drag polar,
  CL–CD and transition plots, BL plots (δ*, θ, Cf, H, N), CSV export,
  guided tour update.
- **V7** — benchmarks, README and documentation.

## Outcome

All sub-steps are done.

- Modules: `viscous::closure`, `blsys` (interval systems), `panels` (wake,
  `DIJ`), `session` (XFOIL session state and bookkeeping), `march`
  (`MRCHUE`, `MRCHDU`), `newton` (`SETBL`, `BLSOLV`, `UPDATE`), `viscal`,
  `solver` (public API: `ViscousSolver`, `ViscousSession`, sweeps).
- Validation: ten reference cases (dump files, polars, console logs) and 50
  random analyses in `tests/viscous_validation` (see its `REPORT.md`).
  Comparing XFOIL's console output line by line located the only porting
  error found (a NaN residual must take the extrapolation branch of the
  marching routines, as XFOIL's `IF(DMAX .LE. 0.1)` does).
- Divergences of iteration paths in unstable phases are accepted only when
  our own computation shows the same sensitivity to perturbations of the
  Reynolds number of 1e-15 to 1e-11.
- Decisions taken during the port:
  - `allow_supercritical` of the inviscid options also governs the viscous
    solver; with it, a Kármán–Tsien breakdown is flagged
    (`compressibility_breakdown`) instead of refused, as XFOIL warns and
    goes on;
  - single points start from a fresh boundary layer (XFOIL `INIT` +
    `ALFA`); `ViscousSession` gives XFOIL's warm starts;
  - the application stores tagged polars (project format 2; format 1
    projects are migrated on load).
